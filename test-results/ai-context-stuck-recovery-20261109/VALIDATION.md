# AI 中断任务恢复死循环修复

日期：2026-11-09

结论：根因已修复。超长工具回合不再永久卡在“任务中断，等待核对”；实体手机上的原任务已恢复运行并执行多批工具写入。

## 真实问题

- 设备：`HONOR REA-AN00`，Android 15 / API 35。
- 会话：`cnv_e6f47fea-4957-4cbd-a5bf-4e778e266400`。
- 任务：`agent_1794204476923870_1`。
- 助手消息：`msg_423e5e71-fa1e-45fe-90b7-2fb8ace16dc3`。
- 初始工具 transcript：约 66 KB；后续增至约 96 KB。
- 初始错误：`安全前缀摘要和最完整的当前工具回合共 61669/61237 字符，超过 48000 字符窗口`。
- 每次点击“已核对，继续”都会重新失败，并把同一错误继续追加到助手消息。

## 根因

1. 最新工具回合的工具调用参数和工具结果总量过大；原压缩器只裁剪工具结果正文，不能处理超大工具调用参数。
2. 无法裁剪时，压缩器直接返回阻塞，没有使用已包含目标、对象版本、回执和冲突的安全摘要。
3. 加入安全摘要回退后，又暴露第二层错误：请求已从 `49,772` 字符压到 `45,862`，低于 `48,000` 硬上限，但仍因未达到额外 10% 缩小余量被拒绝。

## 修复

- 完整工具回合无法容纳时，回退到安全摘要。
- 摘要保留原始目标、补充要求、对象 ID/版本、操作回执、待核对冲突，并标记 `latest_tool_round_compacted`。
- 删除“必须达到额外 10% 缩小”的阻断条件；最终请求低于模型上下文硬上限即可继续。
- 完整工具 transcript 仍保存在本机，不删除审计记录。
