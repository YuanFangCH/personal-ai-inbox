## 1. 执行约定

- 严格按 P0 → P9 顺序推进。每包内按编号执行；依赖步骤未完成不得跳过。
- 每行包含动作、落点及可检查的完成条件。新文件名称可以随实现调整，但不得遗漏职责或验收场景。
- 每个工作包是一个任务：完成局部验证，更新 README/RM_HANDOFF 和结果目录，暂存全部本任务文件，通过 hooks 后创建一个 Conventional Commit，检查工作区干净。不要把整个改版攒成一个大提交，也不要在同一包内提交半成品。
- 临时脚本、数据在 `tests/agent-temp/table-notebook-pN/`；命令、日志、结论和未覆盖项在 `test-results/table-notebook-pN/`。长期测试沿用 `app/test/`。
- 本轮只编写计划。未来执行时也不默认跑全量测试，不使用会间接跑全量的聚合验证脚本；本计划中的命令均在 `app/` 执行，另有说明除外。
- 不把 OneDrive/百度网盘接通、通知调度或发布新版本塞入本轮。同步工作只调整已有协议与本地 Provider/冲突链路兼容性。

P0 建议默认值（尚非用户决定）：

- 首页汇总与日历筛选独立；表模块按内容更新时间倒序，展开完整分页列表，移除模块不删表。
- 默认字段不强制必填，不提供公式、自动计算、嵌套表或附件字段。日期区分日期值和带时区时间；自定义日期字段不自动成为日历时间。
- 字段有稳定 ID；改名不丢值。删除字段先展示受影响数量，保留可恢复前像；改变类型遇到无法转换的已有值时拒绝整次转换，列出需处理条目，不静默清空。
- 跨表移动不创建字段定义：已有兼容定义可以映射；其余源值保留为附加资料并反馈，避免因移动偷偷改表结构或丢值。具体表现先在样例中确认。
- 普通单条删除先沿用既有短期撤销，不擅自把整表 30 天规则扩展到所有操作；是否统一回收站另列产品选择。
- 草稿进入表列表中的草稿入口；捕获歧义进入其来源对话中的调整卡；无来源会话的捕获提供可返回的本地处理入口；冲突放同步页；全局候选保留全局知识页和原对话卡。移除待处理页面前验证每种存量数据可达。
- 已完成待办在日历保留完成标记，在首页未完成列表移除；历史事件按业务日期展示。重复安排沿用当前基础规则，不新增例外日期或农历。
- 首页顺序和日历显隐先按设备保存；新恢复材料先保证本端 30 天恢复，跨端恢复能力另按协议实测，不宣称云端已可用。
