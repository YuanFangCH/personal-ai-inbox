# AI 对话界面与操作权限改造草案

日期：2026-10-20。状态：需求澄清中；本文件不替代既有 ADR，不授权开始业务实现。

## 1. 本轮目标与已明确要求

- 将现有收件箱入口直接改为 AI 对话界面，参考用户提供的 DeepSeek 手机端五张截图。
- 新增 AI 读取已有成果、读取其他会话、修改和删除已有内容的能力。
- 权限共三组、初始默认全部开启；分组暂理解为“读取 / 新增 / 修改与删除”，待用户确认。
- AI 页面顶部提供权限入口，位于参考图朗读开关的位置；应用总设置可修改默认权限。
- 本轮仅制定计划，不修改运行代码。

## 2. 界面草案

- 顶部从左到右为历史会话菜单、当前会话标题、权限按钮、新对话按钮。
- 空会话显示简洁欢迎区；发送消息后以对话内容为主，支持现有流式回复、停止和重试。
- 底部采用圆角输入容器，保留文字、粘贴、图片预览与移除、相册和拍照入口；键盘出现时保持输入区可见。
- 侧边菜单提供历史会话搜索、按日期分组、继续会话、重命名与删除。搜索范围建议包含标题和消息正文。
- 原有草稿、捕获确认、同步冲突建议迁入侧边菜单的“待处理”入口并显示数量，保留现有处理能力；具体位置待确认。
- 手机使用抽屉；平板、Windows 根据宽度展开会话侧栏，沿用同一套权限语义。
- 导航名称建议由“收件箱”改为“AI 对话”。是否改变 App 冷启动首页不包含在已确认要求中。
- 截图中的深度思考、联网搜索、语音、文件导入尚未纳入已确认范围；不会仅为还原外观放置不可用按钮。

## 3. 权限草案

| 权限 | 建议边界 | 状态 |
|---|---|---|
| 读取 | 按需检索和读取本端已有事项、待办、日历事件、知识及其他会话文字；当前会话消息仍作为普通对话上下文 | 待读取范围确认 |
| 新增 | 允许 AI 新建成果；是否调整原有高置信自动记录规则需在正式方案中明确 | 默认开启已明确 |
| 修改与删除 | 更新或删除已有成果，包含手工创建的成果；是否允许操作会话、历史消息及逐次确认待用户选择 | 分组和执行方式待确认 |

建议总设置保存新会话默认值，顶部面板只覆盖当前会话并持久保存；旧会话未覆盖时采用默认值。总设置变更不覆盖已有会话的显式选择。以上均为建议，待确认。

建议读取采用本端检索、按需返回片段、必要时读取详情，不把全部成果或全部会话自动塞进每次请求。工具结果在对话中提供可打开的来源。读取其他会话涉及将选中内容发送到当前配置的云端模型；不意味着会话加入跨端同步。其他会话图片和原始素材的读取不作为隐含授权。

权限控制需由本地核心执行，每次工具调用、最终写入和恢复重放都检查当时有效权限；只在提示词中要求模型遵守开关不足以实现权限。关闭权限后的在途操作、已有工具上下文处理方式需要在正式方案中定义。

## 4. 现有实现与变更位置

| 位置 | 现状与计划涉及范围 |
|---|---|
| `app/lib/ui/app_shell.dart`、`ui/pages/inbox_page.dart` | 当前收件箱为草稿、确认队列和会话列表；改为可直接输入的会话工作区 |
| `app/lib/ui/pages/conversation_page.dart` 及 `conversation/` | 复用现有消息、图片和流式交互，调整顶部、空态、输入容器与历史菜单 |
| `app/lib/modules/conversation/conversation_workspace.dart` | 持有会话生命周期、生成和恢复；扩展受权限约束的工具编排 |
| `app/lib/services/chat_service.dart`、`model_client.dart` | 目前请求取当前会话上下文；需支持读取工具结果回传模型并继续生成的多轮工具流程 |
| `app/lib/modules/conversation/auto_record_processor.dart` | 当前只处理 `create_result`；新操作执行策略须与既有自动记录行为统一，避免重复执行 |
| 端配置、设置快照、会话存储 | 增加默认权限、会话覆盖及迁移；覆盖设置导入、导出、恢复默认的语义 |
| 成果库 | 所有成果操作仍统一经过 `ResultLibrary`，复用稳定 ID、版本校验、可恢复提交、幂等账本与墓碑 |

## 5. 与既有决定的差异

当前 ADR 0010、术语表“上下文”、模型接入第 9 节规定上下文不跨会话、已有成果不隐式召回、修改与删除不自动执行。ADR 0013 将确认队列合并到收件箱。此次需求会扩展这些边界，不能把现状误写成已经支持。

待用户确认后新增 ADR，明确取代旧决定的具体部分，并同步 `CONTEXT.md`、可执行方案、模型接入与交接。若确认调整会话生命周期，还需明确与 ADR 0013 的关系。成果权威存储、同步白名单、墓碑、冲突裁决和凭据规则继续适用。

## 6. 待确认问题

1. 是否采用“读取 / 新增 / 修改与删除”三组，或将修改、删除拆成四组？
2. 开启修改与删除后，是直接执行并支持撤销、仅删除前确认，还是都先预览确认？
3. 修改与删除只涉及成果，还是也包括会话管理、历史消息？
4. 顶部权限只作用于当前会话并记住，还是全局立即生效？
5. 进入 AI 页面恢复上次会话还是显示新对话？原有待处理内容能否迁入侧边菜单？
6. 本轮只参考布局并保留现有文本/图片能力，还是另规划深度思考、联网搜索、语音与文件？

## 7. 确认后的实施与验收草案

建议顺序：先确认权限契约并补 ADR，再实施设置与会话迁移、工具读写链路、对话界面，最后运行受影响的局部验证。用户确认计划前不开始业务实现。

后续验收覆盖：三组权限默认值与覆盖；关闭权限时请求、执行及恢复均受限；成果检索与其他会话读取来源可追溯；新增/修改/删除结果真实反馈；重复工具调用幂等；写入版本冲突不覆盖新内容；删除保留墓碑；按所选方案验证确认/撤销；历史会话、草稿和确认队列可达；分享入口、键盘、浅深色及手机/平板/Windows 布局。

仅运行与变更及直接调用方相关的测试，复用既有覆盖；未获用户明确要求不执行全量测试。当前仅完成源码与截图只读核对，不代表上述行为已实现或通过测试。
