# 前端视觉与动效改版方案

起草：2026-10-24；更新：2026-10-25。状态：设计草案，供评审；本轮不修改 Flutter 运行代码。用户已明确改版方向，以下具体尺寸、布局及动效参数仍是建议，不视为已批准实施。

## 1. 需求与完成标准

1. 整个前端参考 DeepSeek 手机端与网页端的简洁画风，AI 对话优先贴近参考布局。
2. 增加有明确反馈作用的动效，覆盖导航、面板、对话、列表和操作状态。
3. 首页移除顶部“收下内容”入口与数量统计，让各板块实际内容直接平铺。

本轮产物：本方案、会话内可交互设计预览、交接更新和规划验证记录。预览使用合成内容，只演示布局与局部动效，不连接模型、不代表应用已实现或设备验收通过。已查看用户本机目录 `D:\Dsk\图\deepseek界面` 内的 5 张 App 图及 1 张网页图，优先以这组截图作为样式基准；截图含私人会话标题和头像，原图不复制进公开仓库，预览不复用其私人内容。

设计验收重点：打开首页先看到实际内容；对话页的阅读区、气泡、输入区与会话管理形成统一视觉；手机、平板和 Windows 使用同一套组件规则；浅深色、字体放大、键盘及减少动态效果均有明确状态。

## 5. AI 对话页（最高优先级）

### 手机

- 顶部约 52–56dp：左侧历史菜单，中间当前标题，右侧当前会话权限和新对话。长标题截断，按钮保持独立热区。
- 空对话：参考图 1，在可用正文区中部放小型产品标识和一句“今天有什么想交给我？”，减少介绍文字；输入区位于底部，不加入统计或推荐卡片。
- 用户消息右对齐，最大约可用宽度的 82%，浅灰底、20dp 圆角；长文字自然换行、可选择复制。
- AI 消息左对齐，正文直接铺开，无整块卡片边框；正文、列表、Markdown、表格、代码块使用统一排版。宽表与代码块可局部横向滚动，不撑宽整个页面。
- 消息下方用紧凑操作行放复制、系统支持时的朗读和失败时的重试；成功回复增加复制属于少量呈现交互补齐，不新增模型能力。
- 工具动作与撤销使用轻量状态行，区分“处理中 / 已完成 / 失败 / 可撤销”；多个动作可展开详情。全局知识候选保留明确的确认/拒绝与内容版本，不能为简洁隐藏审批。
- 不新增可见思维链。沿用当前隐藏 reasoning/tool transcript 的边界，等待时只显示真实的“思考中 / 正在回复 / 正在处理成果”等状态。
- 输入区外侧页边 12–16dp；上行是纯净多行文字输入，下行左侧“深度思考 / 智能搜索”轻胶囊，右侧附件、语音与圆形发送/停止。内部文本框不得再套白色表单框。
- 320dp 与 1.5 倍字体下，工具行允许换行；附件/发送始终可见，能力按钮不挤掉主动作。输入最多约 6 行后局部滚动。
- 图片/文件预览位于文字上方；添加、移除有尺寸过渡；未配置模型、能力不支持、图片出网关闭、文件提取失败各有对应状态。参照图 2/3，附件加号展开输入区下方托盘（拍照/相册/文件，保留本项目粘贴入口），切为关闭图标；文字输入获得焦点时收起托盘，让位给系统键盘。无需为贴图自动读取整本相册或新增图库权限，现有系统选择器仍负责选取；图中“最近照片”和提问捷径不自动扩展为本轮功能。
- 键盘出现时输入区贴在键盘上方；AI 页面建议隐藏底部全局导航以减少双层底栏，提供明确回首页入口；退出后恢复原主导航。该导航行为是待评审建议。

### 平板与 Windows / Web 预览

- 建议以 `<600dp` 手机、`600–1023dp` 紧凑/平板、`≥1024dp` 宽屏作为统一适配起点，依据实际可用宽度和字体再调整。
- 宽屏侧栏 232–260dp：在 AI 场景同一栏放首页返回、新对话、会话搜索/分组和底部设置入口，避免全局长侧栏再加完整会话长侧栏。其他页面继续使用主导航。
- 600–1023dp 优先使用可折叠会话抽屉；空间足够且大字体不拥挤时才常驻，避免平板被两个栏挤压。手机抽屉参考图 5，打开时主会话轻微右移并露出边缘；系统返回/遮罩点击关闭，关闭后焦点回到原按钮。位移不触发页面重建或会话重置。
- 正文阅读栏建议最大 760–800dp，输入区与正文对齐，屏幕加宽后增加两侧留白；不能仅把手机放大。参照用户网页图，桌面空态将问候与输入区一起居中；首次发送后输入区在 220–280ms 内移至底部，正文区展开。手机空态输入区始终在底部，不能套用桌面布局。
- 桌面聚焦输入框时 Enter 发送、Shift+Enter 换行；中文输入法组合输入期间 Enter 不误发送。手机保持换行并通过按钮发送。
- 流式增长仅在用户位于底部附近时跟随；向上阅读后停止自动拉回，显示“回到底部”。当前每次生成重建均触发滚动的呈现逻辑需一并调整，不改变生成协议。
- 历史消息不逐条重播入场动效；切换会话保持其阅读位置。返回选图、权限面板、窗口缩放及主题切换均不能触发新会话。

## 6. 首页：内容直接平铺

明确移除：顶部“收下内容”按钮、首页继承的桌面“收下”浮动按钮、今日日程/未完成/待确认/知识四个数量卡，以及板块标题后的“X 项”。不新增另一套总览或快捷入口卡墙。全局捕获能力保留在现有其他入口，AI 输入、系统分享和待办快速新建继续可达。

默认建议保留小型“首页 + 日期”标题，移除大幅问候区，让第一块内容尽快进入首屏。这里的“平铺”指每个板块直接展示内容；手机纵向滚动，宽屏规则双列，不做横滑轮播或每块独立滚动。

```text
手机                         宽屏
首页 · 日期                  首页 · 日期
接下来的安排   查看全部       接下来的安排       要做的
  时间 + 日程正文             时间 + 日程        可勾选待办
要做的          新建          ────────────────────────
  可勾选待办                 最近知识（下方通栏）
最近知识        查看全部       标题 + 正文摘要
  标题 + 正文摘要
```

- 基础范围沿用现有三块：今天的日程、未完成待办、最近知识，不擅自把事项、待处理、同步状态都新增成首页窗口。
- 日程按当前日期及原有排序展示；避免在纯视觉改版中同时重写重复事件/日历投影业务。把标题改为“今日安排”可更准确表达现有日期范围。
- 建议首页日程预览最多 4 条、待办最多 6 条、知识最多 4 条；“查看全部”进入对应工作区，日期/筛选含义明确。限额待视觉稿评审后确定，不能无限展开占满首页。
- 待办沿用既有逾期/截止时间排序；勾选在持久化成功后呈现完成反馈并平滑移除，失败保留原状态并提示。
- 知识显示标题及 1–2 行摘要，关联事项/标签用小字；长文预览不挤掉标题。
- 空板块只占简短一行，例如“今天暂无安排”；保留“新建”或查看入口，不用大幅插画占屏。
- “事项窗口”和首页“待处理窗口”属于可选扩展，尚未纳入基础方案。待处理入口仍在独立页面。

## 8. 动效规范

增加运动反馈，同时让阅读和高频操作保持稳定。时间均为初值，实施时根据设备观察调整。

| 场景 | 建议动效 | 约束 |
|---|---|---|
| 按钮/图标按下 | 90–120ms 轻缩放至约 0.97 + 底色反馈 | 松开/取消恢复，键盘焦点可见；禁用不触发 |
| 主页面切换 | 180–220ms 淡入配合 4–8dp 位移 | 返回方向一致；切页不触发额外业务动作 |
| 抽屉/底板 | 240–280ms 滑入 + 遮罩透明度变化 | 可连续打断、手势关闭、焦点归还 |
| 新消息 | 160–200ms 透明度 + 6dp 上移 | 每条只入场一次；历史加载与每个 SSE 分片不重播 |
| 流式回复 | 原生流式增量显示，等待时小型活动指示 | 不在流上再加人为逐字延迟；停止立即响应 |
| 输入区/附件 | 180–220ms 高度和位置过渡 | 键盘跟随系统；避免键盘和容器两次叠加位移 |
| 勾选待办 | 120ms 勾选反馈，持久化成功后约 180ms 收起行高 | 稳定 ID；保存失败不假装完成 |
| 筛选/搜索/日历视图 | 140–200ms 内容过渡与选中指示滑动 | 快速连续操作保留最终状态，日期不漂移 |
| 操作完成/撤销 | 160–200ms 状态行切换，轻提示条滑入 | “成功”只能来自真实操作结果；撤销时限不受动画影响 |

进入/展开使用 ease-out，退出使用 ease-in，状态转换 ease-in-out；不加入持续漂浮、全屏粒子和大范围弹跳。仅真实处理中允许小型循环状态指示；离屏或后台暂停。

统一响应系统“减少动态效果”/禁用动画配置；未来 Flutter 实现以系统 accessibility animation flags 为依据，将装饰位移/缩放关闭或降到极短淡化，状态与操作结果照常可见。默认不新增动效设置项；是否需要用户手动开关后续再定。

性能验收目标：目标设备 profile 模式下采样切页、打开抽屉、流式滚动与勾选列表；以 60Hz 每帧约 16.7ms 为参考记录 UI/raster 耗时与卡顿。该目标尚未测量，不承诺当前设备一定达到；避免逐帧重建整个应用、全屏模糊与长列表同时入场。
