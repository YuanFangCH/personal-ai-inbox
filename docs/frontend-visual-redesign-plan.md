# 前端视觉与动效改版方案 v2


v2 取代 v1 的当前状态、后续任务顺序与完成口径。首轮 D0–D5 的提交和测试记录继续有效；“已提交首轮实现”不能推导为所有设计细节、动效或视觉验收均完成。原始用户截图是本轮样式依据，早期交互草图和网页辅助建议仅作参考。

## 1. 目标与范围

1. AI 对话在布局、留白、输入区、历史管理和阅读层级上贴近用户提供的 DeepSeek 手机/网页截图，使用“懒狗秘书”自己的名称和标识。
2. 全站统一颜色、字体、间距和控件；分别按聊天、内容列表、日历、阅读、编辑的使用方式设计密度。
3. 首页只展示日程、未完成待办、最近知识的实际内容；移除顶部捕获入口、数量统计和板块计数，不新增统计卡或快捷入口墙。
4. 为输入、导航、消息、勾选和真实操作状态补充连贯动效，维持连续输入与阅读位置。

继续沿用现有会话、权限、成果库和同步契约：首次发送才创建会话；进入 AI 主入口打开新对话；离开按原生命周期取消生成；普通成果按权限执行并可撤销；全局知识增改删人工确认。会话与原始素材留本端。当前接口未声明的能力继续按现有能力判断显示，方案不增加模型、云盘或数据迁移工作。

## 4. 页面框架与响应式导航

统一用可用窗口宽度决定外壳；首页双列另看正文实际可用宽度。键盘导致高度变化时不切换布局类别。

| 窗口 | AI 页面 | 普通页面 |
|---|---|---|
| `<600dp` | 无全局底栏；历史抽屉；顶部菜单/标题/权限/新对话 | 保留全局底栏；更多入口继续可达 |
| `600–1023dp` | 默认折叠历史，避免同时占两条侧栏；横竖屏切换保留会话 | 采用紧凑导航；主内容保持可读宽度 |
| `≥1024dp` | 约 248dp 单侧栏，核心导航/新对话/搜索/历史/更多；阅读区最大 800dp | 单一应用导航区，正文按页面类型布局 |

收敛 `app_shell.dart` 现有 980dp 与对话 1024dp 的外壳阈值；首页列数不直接复用外壳阈值。普通页面进入详情/审批后有明确返回，根页面不能堆叠同名工具栏。

宽屏侧栏核心导航采用首页/日历/事项/知识紧凑区；更多提供全局知识/待处理/设置/同步。正常高度历史独立滚动；可用高度低于约 460dp 时把历史改成“历史对话”入口打开管理层，导航仍可达，不强行维持最小 120dp 历史列表挤压其他区。

手机抽屉初值宽度为 `min(窗口宽度×0.86, 340dp)`，保留约 32–48dp 会话边缘；展开时会话面板轻微右移并露出圆角。保留遮罩、返回键/手势关闭和焦点归还；抽屉开合与窗口缩放不能重建另一会话。

布局判定与发送快捷键分离：原生 Windows 和桌面浏览器预览在窄窗口也使用桌面输入规则；Android/移动浏览器保持换行。实现时依据平台及输入环境核实，不能只用 `width >=1024` 判断。

## 5. AI 对话详细规格

### 5.1 空态、消息态与阅读

结构示意（不作为像素稿）：

```text
手机空态                     桌面空态
菜单  会话标题  权限 新对话   ┌ 单一侧栏 ┐ ┌──────── 主内容 ────────┐
                             │核心导航  │ │                         │
       产品标识              │新对话    │ │       标识 + 问候       │
       一句问候              │搜索      │ │       居中输入区        │
                             │日期历史  │ │                         │
┌文字输入────────────────┐  │          │ └─────────────────────────┘
│能力按钮   附件 语音 发送│  │更多      │ 发送后输入区连续移动至底部
└────────────────────────┘  └──────────┘
附件展开：三块选择热区位于输入容器下方，正文可用区相应收缩
```

- 手机顶栏约 56dp：菜单、可截断标题、权限、新对话。权限保留在顶部；AI 页始终无全局底栏。
- 手机空态欢迎区位于可用正文区域中部；输入区置底。附件或键盘占高后欢迎区随可用区域收缩，极低高度时收起问候，避免把输入区挤出屏幕。
- 桌面空态问候与输入区组成一个居中内容组；首次发送后，同一个输入实例在 240ms 左右移动到底部，消息区展开。过渡不丢焦点、选区、图片或文件；窗口缩放/打开面板不触发发送过渡。
- 用户气泡右对齐、最大正文宽度约 82%；AI 直接铺开。正文和输入区共用中心线与最大 800dp 阅读宽度。
- 复制/朗读/失败重试组成一条紧凑动作行。手机始终可访问，桌面可降低未悬停时的视觉重量但不能失去键盘入口。
- Markdown 的聊天、详情和编辑预览共用排版配置。普通段落换行；长代码/宽表在各自区域横滚；代码块有语言标识和独立复制动作。先验证现有渲染器，确有缺口才补局部 builder。

### 5.2 输入区与状态

容器页边 12–16dp，浅描边/浅阴影；文字区与工具行分层，文字最多约 6 行后局部滚动。正常工具行左侧能力胶囊、右侧附件/语音/发送；320dp/1.5x 允许能力区换行，发送/停止保留独立热区与固定位置。

| 状态 | 布局与动作 | 返回/退出规则 |
|---|---|---|
| 空输入 | 发送禁用且不高亮；附件/可用语音清楚 | 无临时层时回首页，不落空会话 |
| 输入/键盘 | 托盘关闭；输入区只跟随系统键盘位移一次 | 先收键盘，保留文字/素材 |
| 附件托盘 | 键盘收起；相机/相册/文件三块热区，粘贴文字为次动作；加号转关闭 | 收托盘保留选中素材 |
| 选中素材 | 图片缩略图/文件状态在文字上方；移除动作独立 | 选择器取消不清旧素材；提取失败显示具体错误 |
| 语音识别 | 收托盘并解除键盘焦点，显示真实识别/停止状态 | 第一次返回先停止识别并保留已回填文字，再次返回才离开 |
| 本地提交 | 防止连点；成功落库用户消息后才清本轮输入 | 本地保存失败保留全部内容并显示重试方向 |
| 生成中 | 发送同位变停止；正文按真实 SSE 增量更新 | 覆盖层/键盘关闭不取消；真正离开仍沿用原取消行为 |
| 停止/生成失败 | 保留用户消息和已有回复，显示准确状态及适用重试 | 重试不重复落用户消息，不回滚已提交成果 |

Windows/桌面 Web：Enter 发送，Shift+Enter 换行；IME composing 期间 Enter 只提交候选词。手机默认 Enter 换行、点按钮发送。无论窗口宽窄，组合输入、粘贴多行和附件状态都不能误提交。

新对话、切换历史、回首页/其他主页面遇到未发送文字/图片/文件时，沿用已有确认丢弃。取消保留原输入/焦点；确认才清理。打开覆盖式审批/待处理返回后仍回原会话。系统分享与迟到的文件/语音回调必须核对目标会话和页面生命周期。

### 5.3 滚动与消息入场

- 用户位于底部附近才追尾；向上阅读立即停止自动拉回，并显示回到底部。输入区高度改变优先保持正在读的消息位置。
- 切换历史保存本次运行内阅读位置。首次加载历史和每个 SSE 分片不重播入场。
- 新用户消息和新 assistant 消息各按稳定消息 ID 入场一次；assistant 后续正文增长直接渲染，不附加逐字计时器。
- 追尾每帧至多合并一次滚动请求；不在每个 build 创建一轮重叠 `animateTo`。减少动态效果下程序性归位即时完成。

### 5.4 成果回执与全局知识审批

普通回执默认显示动作、成果类型/标题、真实结果与适用的打开/撤销；原因、版本等收在可展开详情中。多项操作先给简短完成/失败摘要，再展开各项；摘要来自实际动作状态。

| 来源状态 | 呈现 |
|---|---|
| prepared / 处理中 | 显示处理中；未经证实不提前成功 |
| applied | 明确已新增/修改/删除；按真实 `undoUntil` 决定撤销；删除后不提供失效打开 |
| undoing | 局部忙碌并禁止重复点击 |
| undone | 已撤销，显示真实可得结果 |
| expired | 已执行，撤销窗口结束；不是操作失败 |
| failed / 跳过 | 准确区分未执行、执行失败、撤销失败并显示原因 |

UI 通过模块读取已有账本/动作，不按回复文本推测成功，不增加第二套事务逻辑。对无法核实的回执显示“状态待核实”，不盲目再执行。

全局知识独立审批：新增显示完整候选；修改显示当前值/候选值及版本；删除明确对象和内容摘要。保留 `pending/approved/applied/rejected/stale/failed` 的不同含义，approved 为已确认等待提交，stale 必须重新审阅，确认绑定所见 digest。长内容可展开；紧凑外观不能隐藏确认/拒绝或变更内容。

## 6. 首页详细规格

标题为小型“首页 + 日期”，允许窄屏换行。正文立即进入“今日安排 / 要做的 / 最近知识”；无顶部捕获、数量卡、板块计数、首页捕获浮钮或横滑板块。

```text
手机                         宽屏正文
首页 · 日期                  首页 · 日期
今日安排         查看全部    今日安排     查看全部  要做的   查看全部/新建
时间  标题/摘要              时间 标题/摘要           □ 标题/截止
要做的     查看全部/新建     时间 标题/摘要           □ 标题/截止
□ 标题/截止                  ──────────────────────────────────────
最近知识         查看全部    最近知识                         查看全部
标题 + 正文摘要              标题 + 正文摘要
```

手机纵向排列；正文实际宽度可容纳两列各至少约 350dp 且不挤压大字时，今日安排与要做的并排，知识下方通栏。大字需增大列宽，容纳不足则回单列。初值以正文宽度约 880dp 为双列起点，按样稿核对；不按屏高动态改变条数。

| 板块 | 手机/单列 | 双列 | 行内容与入口 |
|---|---|---|---|
| 今日安排 | 最多 3 项 | 最多 4 项 | 沿用当天范围与时间排序；时间 + 最多两行标题 + 简短正文；查看全部进入日历 |
| 要做的 | 最多 4 项 | 最多 6 项 | 沿用逾期/截止排序；勾选 + 最多两行标题 + 截止提示；新建及查看全部进入待办段 |
| 最近知识 | 最多 3 项 | 最多 4 项 | 标题 + 1–2 行摘要 + 少量标签/归属；查看全部进入知识页 |

数据范围沿用当前成果列表；含全局知识时用明确范围标记，不在视觉任务中静默更改筛选。所有条目可直接打开。空态仅短句与必要动作，不占大块插画。知识行不重复用“知识”类型字样挤占摘要。

待办完成采用逐行反馈：点击后该行局部等待；持久化成功后短暂呈现完成勾选/文字状态，再收起该行约 180ms，随后补入下一条预览；即使预览总高度最终相同也要有单行动作反馈。失败保留原行、取消局部等待并提示错误。稳定 ID 放在列表直接子项上，保留其他行身份、焦点和滚动锚点；不因拼接整列 ID 更换整列 key。连续点击同一待保存行不可重复提交。

## 7. 其他页面逐页规格

以下仍需逐页交付。已有主题继承可复用，不能代替页面状态样稿。

| 页面 | 布局与主要动作 | 本次需要核对的状态 |
|---|---|---|
| 日历 | 标题/日期与今天/新建动作一行；日程/我的一天/待办分段放在内容顶部，日程模式为次级工具条；手机只保留一个全局底栏，避免内外两层导航叠高 | 五种日程模式、今天/选中态、长事件、空日期、快速连续切换；日期和滚动不漂移 |
| 事项 | 轻卡片或紧凑行，标题/摘要/关联行动数量有层次，少量标签；保留新建和打开 | 空列表、长标题/标签、关联条目；当前未提供的搜索不当作既有功能 |

| 同步 | 通道与真实状态优先；上/下载/冲突/失败为次级摘要，诊断明细可展开；同步忙碌动作清楚 | 未运行/运行中/成功/失败/冲突；明确端内沙箱身份，不用成功动效暗示真实云盘已接通 |

## 8. 动效清单与执行规则

| 编号 | 动作 | 初值 | 中断/减少动态效果 |
|---|---|---|---|
| M01 | 发送/新对话/快速新建按下 | 90–110ms，缩至约 0.97，松开恢复 | 取消也恢复；reduce motion 取消缩放，其他控件复用 Material 反馈 |
| M02 | 主页面切换 | 200ms 淡入 + 4–8dp 位移 | 快速切换最终只显示最后页面；reduce motion 取消位移，0–60ms 淡入 |
| M03 | 历史层/底板 | 240–260ms 滑入与遮罩；会话边缘相应位移 | 可反向打断；关闭归还焦点；reduce motion 即时开关并保留遮罩 |
| M04 | 附件托盘/更多设置 | 180–200ms 高度变化 | 连点按最终状态收敛；不删除内容；reduce motion 零时长 |
| M05 | 桌面空态输入区到置底 | 约 240ms，单一输入实例位置过渡 | 发送只触发一次；缩放重新布局不重播；reduce motion 即时到终态 |
| M06 | 新消息 | 160–180ms 淡入 + 6dp 上移 | 每条 ID 一次；历史和 SSE 分片不重播；reduce motion 无位移 |
| M07 | 待办成功完成 | 局部勾选约 100ms，行收起约 180ms，补位淡入约 120ms | 仅写成功后播放；失败保留行；reduce motion 即时反馈与补位 |
| M08 | 搜索/日历分段模式 | 140–180ms 内容淡入、选中指示过渡 | 不叠放可交互旧内容，快速操作不误触离场页；reduce motion 即时切换 |
| M09 | 回执/撤销/审批结果 | 160–180ms 状态替换/局部高度变化 | 成功来自实际状态；生成中断不覆盖成果状态；reduce motion 直接替换 |

动画不承担发送、保存、撤销或审批语义。业务成功/失败先决定，再表达结果。禁止动画期间延迟停止请求、重复调用保存或重发模型请求。滚动不另加人为逐字延迟；离屏/后台停止装饰 ticker，dispose 清理控制器和监听。系统键盘跟随系统布局，不能再叠加容器二次位移。
