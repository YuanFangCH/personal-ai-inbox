# 前端视觉与动效改版方案

起草：2026-10-24；更新：2026-10-25。状态：按用户指示开始执行。D0 视觉决策已收敛，当前执行 D1 公共设计基础与控件；具体尺寸和动效仍在跨端检验中可调整，不作为固定像素承诺。

## 1. 需求与完成标准

1. 整个前端参考 DeepSeek 手机端与网页端的简洁画风，AI 对话优先贴近参考布局。
2. 增加有明确反馈作用的动效，覆盖导航、面板、对话、列表和操作状态。
3. 首页移除顶部“收下内容”入口与数量统计，让各板块实际内容直接平铺。

本轮产物：本方案、会话内可交互设计预览、交接更新和规划验证记录。预览使用合成内容，只演示布局与局部动效，不连接模型、不代表应用已实现或设备验收通过。已查看用户本机目录 `D:\Dsk\图\deepseek界面` 内的 5 张 App 图及 1 张网页图，优先以这组截图作为样式基准；截图含私人会话标题和头像，原图不复制进公开仓库，预览不复用其私人内容。

设计验收重点：打开首页先看到实际内容；对话页的阅读区、气泡、输入区与会话管理形成统一视觉；手机、平板和 Windows 使用同一套组件规则；浅深色、字体放大、键盘及减少动态效果均有明确状态。

### 内容密度与阅读排版

2026-10-25 经辅助评审后，由 Codex 收敛以下建议；仍属于待实施设计草案：

| 内容场景 | 密度与层次 |
|---|---|
| AI 阅读 | 宽松行距与段间距；正文直接铺开；用户气泡只承载用户内容 |
| 首页 | 适中密度；时间轴、勾选清单、标题/摘要三种形态分别呈现；板块不再层层套卡片 |
| 日历、事项、知识列表 | 紧凑行与稳定对齐；信息可扫读，避免因追求留白降低日历可用性 |
| 编辑、审批 | 结构清楚，字段/变更/操作区分组；关键内容完整可查，不用装饰淡化确认后果 |

共享字体、颜色、图标和间距梯度，不强求所有页面相同留白。Markdown 建议正文 16sp、行高 1.6–1.75，段间距 12–16dp；一级/二级/三级标题约 24/20/18sp，并与前段保留 20–24dp、后段 8–12dp；列表保持 4–8dp 项间距及嵌套缩进，引用使用浅底/细左线，代码使用等宽字体、轻背景与复制入口。宽表/代码局部横滚，普通段落不能横向滚动。字号与间距按系统字体比例调整，不设置固定文本行高去裁剪大字体。

## 5. AI 对话页（最高优先级）

### 手机

- 顶部约 52–56dp：左侧历史菜单，中间当前标题，右侧当前会话权限和新对话。长标题截断，按钮保持独立热区。
- 空对话：参考图 1，在可用正文区中部放小型产品标识和一句“今天有什么想交给我？”，减少介绍文字；输入区位于底部，不加入统计或推荐卡片。
- 用户消息右对齐，最大约可用宽度的 82%，浅灰底、20dp 圆角；长文字自然换行、可选择复制。
- AI 消息左对齐，正文直接铺开，无整块卡片边框；正文、列表、Markdown、表格、代码块使用统一排版。宽表与代码块可局部横向滚动，不撑宽整个页面。
- 消息下方用紧凑操作行放复制、系统支持时的朗读和失败时的重试；成功回复增加复制属于少量呈现交互补齐，不新增模型能力。
- 工具动作与撤销使用轻量状态行，区分“处理中 / 已完成 / 失败 / 可撤销”；多个动作可展开详情。全局知识候选保留明确的确认/拒绝与内容版本，不能为简洁隐藏审批。
- 不新增可见思维链。沿用当前隐藏 reasoning/tool transcript 的边界，等待时只显示真实的“思考中 / 正在回复 / 正在处理成果”等状态。
- 输入区外侧页边 12–16dp；上行是纯净多行文字输入，下行左侧“深度思考 / 智能搜索”轻胶囊，右侧附件、语音与圆形发送/停止。内部文本框不得再套白色表单框。
- 320dp 与 1.5 倍字体下，工具行允许换行；附件/发送始终可见，能力按钮不挤掉主动作。输入最多约 6 行后局部滚动。
- 图片/文件预览位于文字上方；添加、移除有尺寸过渡；未配置模型、能力不支持、图片出网关闭、文件提取失败各有对应状态。参照图 2/3，附件加号展开输入区下方托盘（拍照/相册/文件，保留本项目粘贴入口），切为关闭图标；文字输入获得焦点时收起托盘，让位给系统键盘。无需为贴图自动读取整本相册或新增图库权限，现有系统选择器仍负责选取；图中“最近照片”和提问捷径不自动扩展为本轮功能。
- 键盘出现时输入区贴在键盘上方；AI 页面建议始终隐藏底部全局导航，空态、有消息和键盘状态保持一致，退出后恢复主导航。保留菜单/标题/顶部权限/新对话布局，抽屉固定首项“返回首页”，Android 返回关闭临时层后退出 AI；不在 320dp 顶栏再叠加返回图标，不把权限移入输入区。桌面使用常驻首页入口；窄 Windows/Web 同样通过抽屉明确返回，不依赖 Android 系统键。该项是 Codex 收敛后的设计建议，不改变首次发送落库规则。

### 手机输入区状态与返回

下表描述呈现状态，不要求增加持久化状态机。键盘、附件托盘、正在识别语音三种输入辅助层互斥；文字/已选素材是独立内容，关闭辅助层不删除内容。权限与历史为临时覆盖层，操作完成回到原会话。

| 状态 | 呈现与互斥关系 | 返回或关闭 |
|---|---|---|
| 空白 | 欢迎区、置底输入、附件/语音；发送禁用 | 无临时层时返回首页，不创建空会话 |
| 编辑文字/系统键盘 | 草稿、按原规则启用发送，输入区随系统键盘上移；托盘收起 | 先收键盘，留在会话且保留文字/素材 |
| 附件托盘 | 收起键盘后展开拍照/相册/文件/粘贴，加号变关闭 | 只收托盘，保留文字/素材 |
| 已选图片/文件 | 输入区上方预览、移除入口、提取状态；可与文字共存 | 系统选择器取消不改已选内容；仅显式移除才删本轮素材 |
| 语音转文字 | 识别状态与停止；托盘关闭、键盘不同时抢焦点 | 先结束识别，已回填文字保留并可编辑，不自动发送 |
| 本地发送/生成 | 提交反馈、流式回复、停止；不重复提交同一轮 | 关闭键盘/托盘/覆盖层不停止生成；真正离开 AI 页沿用既有取消生成行为 |
| 停止/生成失败 | 保留用户消息与已生成正文，分别显示停止/错误及适用的重试 | 重试沿用现有消息与幂等操作语义，不重复插入用户消息 |

返回按当前最上层关闭：权限/抽屉等覆盖层 → 活跃输入辅助层 → 首页；实际键盘事件遵守 Android 系统分发，不同时弹出多个层来竞争返回。离开 AI 页的停止不回滚已提交成果；异步返回后须检查页面仍存在，不能重建另一会话。初次本地提交失败与模型响应失败分开呈现：前者应保留或可恢复未成功提交的本轮内容，后者以已落库用户消息继续重试；实施时先核对现有发送链路的清空时机，只补必要的呈现/暂存，不引入跨会话草稿库。“新对话”和离开未发送页沿用既有生命周期，不因本轮改版承诺自动保存草稿。

### 普通成果回执与全局知识审批

普通成果回执的最小可见信息是操作类型、成果标题/类型、真实状态、适用的打开/撤销入口；原因与版本放可展开详情，不能只显示绿勾。依据现有 `ReversibleActionStatus` 与 `AutoRecordAction` 映射，UI 不绕过模块读数据库；`ResultLibrary.reversibleActionForKey` 可查询现有账本，接线前核对聊天动作 ID 与账本键的关系，不能凭标题猜目标。

| 账本/动作状态 | 回执呈现 |
|---|---|
| `prepared` / 请求处理中 | “处理中”，未证实提交前不显示成功或开放撤销；与模型等待区分 |
| `applied` | 明确“已新增/已修改/已删除”，可打开时提供入口，按 `undoUntil` 判断撤销；删除后不提供失效的打开按钮 |
| `undoing` | “正在撤销”，阻止连点；不提前显示恢复成功 |
| `undone` | “已撤销”；只展示真实可得的结果，不编造完成时间 |
| `expired` | 原动作仍保留已执行结果，说明撤销窗口已结束，不能显示动作失败 |
| `failed` / 跳过 | 依据实际原因说明未执行/执行失败/撤销失败；不能把所有情况都写“未创建” |

网络中断只表示消息生成链路状态，不能覆盖动作回执；若动作结果暂时无法核对，局部显示“状态待核实”，这是呈现标签，不新增账本枚举或后台任务。先通过现有模块取得结果，不开放盲目重写；可重试操作继续使用原幂等标识和版本校验。成功动画、停止按钮和重试按钮均不承担提交/回滚语义。

全局知识使用独立、边界清楚的审批面板，展示新增/修改/删除、目标、变更内容及可核对的版本。长内容可展开查看，修改优先旧值/新值对照，不强求新增通用 diff 引擎；删除明确删除对象。人工确认绑定当前展示的 digest，版本变更后重新审阅，不能自动确认新版。

| 现有候选状态 | 审批呈现 |
|---|---|
| `pending` | “等待确认”，可查看完整变更，提供明确确认/拒绝 |
| `approved` | “已确认，等待提交”，不当作写入成功，不再次提交同一确认 |
| `applied` | “已完成”，可打开仍存在的成果 |
| `rejected` | “已拒绝”，不能混作模型执行失败；不为本轮新增拒绝记录页 |
| `stale` | “内容已变化，需重新确认”，原确认不可沿用 |
| `failed` | “提交失败”及真实原因，保持原确认/恢复机制，不自动批准新版本 |

不从回复文本猜测成功，不公开隐藏 reasoning/tool transcript；审批规则、操作权限、墓碑、幂等及并发检查沿用本地核心。

### 平板与 Windows / Web 预览

- 建议以 `<600dp` 手机、`600–1023dp` 紧凑/平板、`≥1024dp` 宽屏作为统一适配起点，依据实际可用宽度和字体再调整。
- 宽屏侧栏 232–260dp：AI 场景同一栏容纳核心应用导航、新对话、会话搜索/分组，避免双长侧栏。核心首页/日历/事项/知识使用紧凑 2×2 区域，各项保留至少 44dp 热区；底部“更多”明确提供全局知识、待处理、设置和同步。核心入口不随历史列表滚走，历史独立滚动；低高度放不下时将历史折为可打开的抽屉入口，不缩小热区。弹出“更多”自身可滚动且支持键盘/Escape，所有次级入口在低高度仍可访问。非 AI 页面收起历史区，保留原应用导航与可达性；初值需用窄/低高度窗口验证。
- 600–1023dp 优先使用可折叠会话抽屉；空间足够且大字体不拥挤时才常驻，避免平板被两个栏挤压。手机抽屉参考图 5，打开时主会话轻微右移并露出边缘；系统返回/遮罩点击关闭，关闭后焦点回到原按钮。位移不触发页面重建或会话重置。
- 正文阅读栏建议最大 760–800dp，输入区与正文对齐，屏幕加宽后增加两侧留白；不能仅把手机放大。参照用户网页图，桌面空态将问候与输入区一起居中；首次发送后输入区在 220–280ms 内移至底部，正文区展开。手机空态输入区始终在底部，不能套用桌面布局。
- 桌面聚焦输入框时 Enter 发送、Shift+Enter 换行；中文输入法组合输入期间 Enter 不误发送。手机保持换行并通过按钮发送。
- 流式增长仅在用户位于底部附近时跟随；向上阅读后停止自动拉回，显示“回到底部”。当前每次生成重建均触发滚动的呈现逻辑需一并调整，不改变生成协议。
- 历史消息不逐条重播入场动效；切换会话保持其阅读位置。返回选图、权限面板、窗口缩放及主题切换均不能触发新会话。

## 6. 首页：内容直接平铺

明确移除：顶部“收下内容”按钮、首页继承的桌面“收下”浮动按钮、今日日程/未完成/待确认/知识四个数量卡，以及板块标题后的“X 项”。不新增另一套总览或快捷入口卡墙。全局捕获能力保留在现有其他入口，AI 输入、系统分享和待办快速新建继续可达。

默认建议保留小型“首页 + 日期”标题，移除大幅问候区，让第一块内容尽快进入首屏。这里的“平铺”指每个板块直接展示内容；手机纵向滚动，宽屏规则双列，不做横滑轮播或每块独立滚动。

```text
手机                         宽屏
首页 · 日期                  首页 · 日期
接下来的安排   查看全部       接下来的安排       要做的
  时间 + 日程正文             时间 + 日程        可勾选待办
要做的          新建          ────────────────────────
  可勾选待办                 最近知识（下方通栏）
最近知识        查看全部       标题 + 正文摘要
  标题 + 正文摘要
```

- 基础范围沿用现有三块：今天的日程、未完成待办、最近知识，不擅自把事项、待处理、同步状态都新增成首页窗口。
- 日程按当前日期及原有排序展示；避免在纯视觉改版中同时重写重复事件/日历投影业务。把标题改为“今日安排”可更准确表达现有日期范围。
- 建议手机/紧凑布局日程、待办、知识预览上限为 3/4/3 条，宽屏为 4/6/4 条；它们是可调呈现上限，不是数据截断。沿用现有排序，不新增重要性排序或按屏幕高度计算条数的算法，不随键盘/勾选/同宽重建反复调整上限。页面自然纵向滚动，不要求首屏同时展示三块。达到预览上限后通过“查看全部”进入对应完整工作区，日期/筛选含义明确；大字体应增加高度而非截掉关键动作。
- 待办沿用既有逾期/截止时间排序；勾选在持久化成功后呈现完成反馈并平滑移除，失败保留原状态并提示。
- 知识显示标题及 1–2 行摘要，关联事项/标签用小字；长文预览不挤掉标题。
- 空板块只占简短一行，例如“今天暂无安排”；保留“新建”或查看入口，不用大幅插画占屏。
- “事项窗口”和首页“待处理窗口”属于可选扩展，尚未纳入基础方案。待处理入口仍在独立页面。

首页三块建议以标题、间距和轻分割线组织，避免重画成带外框的仪表盘；需要边界的交互面板才使用轻容器。上一轮会话预览仍保留板块外框及 AI 页底栏，只代表早期核心布局示意，不能作为本轮收敛后规格的逐像素稿。

## 8. 动效规范

增加运动反馈，同时让阅读和高频操作保持稳定。时间均为初值，实施时根据设备观察调整。

| 场景 | 建议动效 | 约束 |
|---|---|---|
| 按钮/图标按下 | 90–120ms 轻缩放至约 0.97 + 底色反馈 | 松开/取消恢复，键盘焦点可见；禁用不触发 |
| 主页面切换 | 180–220ms 淡入配合 4–8dp 位移 | 返回方向一致；切页不触发额外业务动作 |
| 抽屉/底板 | 240–280ms 滑入 + 遮罩透明度变化 | 可连续打断、手势关闭、焦点归还 |
| 新消息 | 160–200ms 透明度 + 6dp 上移 | 每条只入场一次；历史加载与每个 SSE 分片不重播 |
| 流式回复 | 原生流式增量显示，等待时小型活动指示 | 不在流上再加人为逐字延迟；停止立即响应 |
| 输入区/附件 | 180–220ms 高度和位置过渡 | 键盘跟随系统；避免键盘和容器两次叠加位移 |
| 勾选待办 | 120ms 勾选反馈，持久化成功后约 180ms 收起行高 | 稳定 ID；保存失败不假装完成 |
| 筛选/搜索/日历视图 | 140–200ms 内容过渡与选中指示滑动 | 快速连续操作保留最终状态，日期不漂移 |
| 操作完成/撤销 | 160–200ms 状态行切换，轻提示条滑入 | “成功”只能来自真实操作结果；撤销时限不受动画影响 |

进入/展开使用 ease-out，退出使用 ease-in，状态转换 ease-in-out；不加入持续漂浮、全屏粒子和大范围弹跳。仅真实处理中允许小型循环状态指示；离屏或后台暂停。

实施优先级：聊天先做侧栏开合、附件托盘、输入位置与真实动作状态过渡，再补新消息一次性入场；首页先做切页、待办勾选/收行、分区内容变化。默认不做首页首屏列表逐项飞入、滚动视差、统计数字跳动、流式逐 token 动画、历史消息重播。勾选导致下一项补位时保持稳定 ID 和当前阅读锚点，不把整块内容重新入场。

统一响应系统“减少动态效果”/禁用动画配置；未来 Flutter 实现以系统 accessibility animation flags 为依据，将装饰位移/缩放关闭或降到极短淡化，状态与操作结果照常可见。默认不新增动效设置项；是否需要用户手动开关后续再定。

性能验收目标：目标设备 profile 模式下采样切页、打开抽屉、流式滚动与勾选列表；以 60Hz 每帧约 16.7ms 为参考记录 UI/raster 耗时与卡顿。该目标尚未测量，不承诺当前设备一定达到；避免逐帧重建整个应用、全屏模糊与长列表同时入场。
