## 1. 原则

- 接入层开放、可替换。默认实现是 `deepseek-flash`，但不把调用写死在该模型上。
- 业务逻辑只依赖内部的结构化契约（分类结果、抽取结果），不依赖任何厂商独有的响应结构；结构校验一律在客户端做。
- 未配置模型或 Key 时，捕获、Markdown 编辑、日历、待办、提醒照常工作，AI 功能整体禁用。

## 4. 图片输入

支持的格式：JPEG、PNG、GIF、WebP，按文件实际内容判断，不看扩展名或声明的 MIME。

三种传入方式：

1. **内联 base64 data URL**：计入 48 MiB 请求体上限，本地文件最省事。
2. **外部可公开访问的 URL**：图片 ≤ 32 MiB，需 60 秒内可下载，URL ≤ 8192 字符。
3. **Files API `file_id`**：单图可到 64 MiB，适合多请求复用同一张图。

细节级别：`low` 会先缩到 512×512，更快更省；`high` / `original` 保留原图；`auto` 当前等价于 `original`。图片进入模型前会自动缩放，每张图 token 上限约 1024。

本项目的选择：

- 截图用**内联 base64**，不用 Files API——原始素材不该在服务端留存。
- OCR 用 `original` 保证中文识别质量；只做粗分类时才用 `low`。
- 配置模型后默认允许直接出网；客户端自动缩放、重编码并去除 EXIF，但不自动判断图片内容是否敏感。

|---|---|---|

对本项目的含义：非紧急的批量任务（报告重算、历史重跑、每日归档附带的分析）排到空闲时段执行。

## 6. 限速与错误

- 并发以**账号**为粒度，与 API Key 无关；超限返回 HTTP 429。
- 可用 `user_id` 参数做账号内的隔离：内容安全隔离、KVCache 隔离、调度隔离。取值需匹配 `[a-zA-Z0-9\-_]+`，最长 512，不得包含隐私信息。
- 非流式请求在等待期会持续返回空行，流式会返回 `: keep-alive` 注释；自研 HTTP 解析要能容忍。
- 请求发出后 10 分钟仍未开始推理，服务端会关闭连接。

## 7. 开放接入

接入方式为 **OpenAI 兼容配置化**：用户在设置里填写 `base_url`、API Key 与模型名，任何 OpenAI 兼容端点都可直接替换，包括自建的 vLLM / Ollama 兼容网关。默认预填 `https://api.deepseek.com` 与 `deepseek-flash`。

能力声明：客户端内置常见模型的能力表（文本 / 视觉 / 结构化输出 / 上下文长度），允许用户覆盖。未声明能力时按最小能力（仅文本）处理，图像相关入口自动隐藏或禁用。

未配置 Key 时：AI 功能整体禁用，捕获、Markdown 编辑、日历、待办与提醒不受影响。

输出结构校验一律在客户端完成，不依赖厂商原生的 structured output；原生 JSON Output 只作为可选的稳定性优化。

## 8. 凭据策略

- API Key 分别保存在各端的系统安全存储中（Android Keystore、Windows Credential Manager + DPAPI）。用户可手动在多端输入相同值，也可按端使用不同值；应用不跨设备同步凭据。
- Key 不进代码、不进仓库、不写进日志；为未来开源准备的只是配置项本身，不是值。
- **每端固定一个 `user_id`**（如 `android-phone`、`android-tablet`、`win-desktop`），用于账号内的 KVCache 隔离、内容安全隔离与调度区分。`user_id` 需匹配 `[a-zA-Z0-9\-_]+`，最长 512，不得包含隐私信息。
- 账号配额由模型厂商管理，不影响端内凭据的独立存储规则；设备丢失时可单独撤销或替换该设备上的 Key。

## 9. AI 对话与自动记录

- 收件箱入口改为直接 AI 对话界面，每次从应用导航进入显示新对话，历史会话从侧边管理显式选择继续；待处理独立成页。冷启动仍进入首页，新对话首次发送内容才创建，未发送退出不留空会话；文件/语音素材的落库条件随新输入链路落实。
- 默认历史上下文仍为当前会话最近 20 条消息、最近 4 条含图消息且不超过 8 张；读取权限开启时，可按需加入已有成果及其他会话的选中片段，另受总上下文预算限制，不自动拼接全部历史。
- 回复使用 OpenAI 兼容 SSE 流式返回；用户可停止生成，半成品保留为“已中断”。
- 模型通过 `create_result` 工具请求新建 `matter | todo | event | knowledge`。客户端只在完整流结束后执行，并要求置信度不低于 `0.85`、非敏感、日期明确且未重复。
- 隐式自动新增的低置信、敏感、日期歧义、过去日期和重复规则继续进入待整理区。按用户要求修改、删除成果时，由本地核心检查对应权限、目标和版本后直接执行，显示结果并支持撤销；不允许 AI 改删会话和历史消息。
- 自动创建结果保留 10 分钟撤销窗口。成果被人工修改后不可撤销。
- 会话、消息和图片只在本端保存，不进入 Markdown 成果库或同步区。
- 三组权限为读取、新增、修改与删除，初始默认全部开启。总设置管理新会话默认值，各会话独立保存，顶部按钮只修改当前会话；工具执行与恢复重放必须检查有效权限。

图片策略：

- 配置模型 Key 后默认允许图片发送到云端，设置页提供默认开启的“允许图片发送到云端”总开关。
- 客户端发送前自动限制尺寸、重新编码并去除 EXIF 元数据，但不自动识别或遮蔽图片内容中的敏感信息。
- 该默认值由 [ADR 0010](adr/0010-contextual-ai-conversation-and-guarded-auto-write.md) 授权，取代此前逐次确认与强制裁剪脱敏的要求。

## 10. 版本化设置与请求期限

端配置以版本化快照保存。配置更新会先校验完整候选，再一次切换快照；API Key 先写入安全存储的新槽，快照引用新槽成功后才清理旧槽。普通设置快照、迁移备份和可移植导出均不包含 Key 值，导出也不包含设备 ID。

用户可以覆盖图片、工具调用、JSON 输出和 thinking 能力；未覆盖时使用已知模型/端点声明，未知模型默认关闭。内置联网能力没有用户覆盖项，未声明时禁用。图片出网总开关优先级最高。当前默认期限和上下文限制为：响应头 45 秒、流空闲 60 秒、请求总时限 300 秒、上下文 20 条、含图历史消息 4 条、图片总数 8 张。有效范围由 [架构整改方案](architecture/maintainability-upgrade-plan.md) 列出，越界配置不会保存。

设置页的连接测试是一次独立网络请求，只发送固定测试文本，不带历史或图片，并按文本能力执行。测试不会自动开放图片、工具或 JSON 能力。

## 11. 思考与联网能力

- **深度思考已接入**：仅在配置能力允许时显示开关。默认识别 `https://api.deepseek.com` 上的 `deepseek-flash`；未知端点默认禁用，可在高级模型设置中由用户声明覆盖。关闭时明确发送 `thinking.type=disabled`，开启时发送 `thinking.type=enabled` 与 `reasoning_effort=high`。
- DeepSeek Thinking Mode 在流式回复中通过 `reasoning_content` 返回隐藏推理；启用工具时，后续模型请求需回传完整 reasoning 与 assistant/tool transcript。本地会话库 v5 保存该隐藏字段并兼容旧库，UI 不显示，数据不进入成果 Markdown/同步。只在最终答案完成后执行普通成果写入；停止或不完整流不会提交。
- **联网搜索当前禁用**：应用请求 `/chat/completions`，官方 Chat Completions 文档列出的是 function tools，没有 server-side web_search。独立 `/v1/tools/search`/`fetch` 需要额外请求，Responses API 的 web_search 也需要切换协议，均不符合用户“仅使用当前接口原生联网能力”的选择；因此无论模型名如何，当前联网按钮都不可用。
- 文件以本端提取文本/表格并按预算发送为待实现路线，扫描内容按视觉能力处理；不自动把原文件上传其他厂商服务。语音限定转文字输入、发送前编辑和回复朗读，不含实时通话；实现来源和平台能力仍待核实。


## 12. 秘书角色与已确认基础事实

面向用户的默认角色改为“懒狗秘书”的秘书型助理，负责信息整理、事项/日历/待办和日期计算；内部分类器继续遵守原结构化职责。角色不赋予权限、不承诺未完成的提醒或后台能力。

AI 可识别值得复用的全局基础事实，或按用户命令提出候选，但新增、修改、删除均必须展示内容并经人工确认后执行，不能走普通成果工具绕过审批。用户的“记住”指令不代替对最终候选的确认；只有已确认且适用的知识可供检索。

全局知识以 `knowledge` 类型的显式范围元数据承载，候选与审批交互留在本端；AI 按需检索且受当前会话读取权限控制，不每轮自动附带基础事实，关闭读取时不触发新的外部读取。已在当前会话出现的内容不能因关权限被追溯撤回。同一已确认版本同步接收不重复要求审批，冲突按同步协议裁决；OneDrive 尚未接通，因此协议目标不代表真实云端已实现。

时间类事实需要适用学期、日期/时区和周序计算口径；事实缺失、过期或冲突时应澄清，不凭模型生成时间表。核心审批、检索和管理界面已由 S3/S4/S5/S6 实现；真实跨端云盘同步仍待后续 Provider 接入。完整边界见 [ADR 0018](adr/0018-confirmed-global-knowledge-for-secretary.md) 与[补充计划](secretary-and-global-knowledge-plan.md)。

## 13. 非必要不检索

当前输入/会话足够则不触发外部于会话的读取；不先额外发一次分类模型请求判断检索必要性。首次正常模型请求仅在有明确的信息缺口或用户查找指令时提出定向读取，本地核心检查权限、范围、去重、轮次、结果量和总期限；片段足够即停，不无命中全库兜底。已有有效结果可复用，但内容/权限/有效期变化后失效，写前版本与审批检查不能省略。

本地检索预算、来源工具和读取权限已在 S4/S5 实现并通过确定性测试；初始预算值仍是可调整的起点，尚无性能实测或真实模型语义必要性评估。本地硬限制不等于能完全证明每次语义上必要。预算与验收见[统一检索策略](ai-retrieval-policy.md)。
