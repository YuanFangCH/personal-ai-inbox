# AI 按需检索约束与成本预算

日期：2026-10-20。状态：按用户要求补充的目标策略，未实现或测量。适用于全局知识、普通成果和其他会话；联网仍受原有“仅当前模型内置能力”规则约束。

## 1. 何时不检索

默认直接使用当前问题、当前会话已提供且仍有效的信息和本轮主动发送的素材。寒暄、改写、翻译、总结已给内容、解释通用概念、依据已给日期计算等，不触发会话外检索。仅出现“学期”“日期”“待办”等词不构成触发条件。

开启读取权限只表示允许检索，不代表每轮都要检索。明确要求不查询已有内容时不检索；依据不够则说明缺项，不编造。基础事实自动识别优先只检查当前交互，不因要提出知识候选而后台遍历历史、全库去重或查询所有学期。

不为判断“要不要检索”新增一次云端分类调用。首次正常模型请求根据当前可见信息判断是否存在完成任务必需的信息缺口；系统角色说明此策略，端内执行权限、预算、范围和重复请求检查。不得宣称规则可完全证明语义上“绝无不必要检索”，应通过定向用例和指标验证。

## 2. 必要检索与最小范围

允许检索的触发包括：用户明确要求查找、回忆、比较既有内容；回答所需个人事实当前缺失；用户要求“最新/当前”状态而现有版本无法确认；成果操作需要定位已有对象。模型提出请求时携带所需事实、查询范围和筛选条件，理由用于可读审计，不是可绕过本地约束的授权。

按问题选择最小来源，不固定把全局知识、成果和历史会话依次都搜一遍：

- 学期周序问题缺少基准：先查适用学期的已确认全局事实，够用就停止。
- 查具体待办/日程：只查相应类型、日期或事项范围，不顺便查历史会话。
- “上次对话说过什么”：检索相关会话文字，返回必要片段，不拼接整场会话。
- 已有稳定 ID：直接读取所需字段/片段，不先做关键词搜索。
- 只有标题或摘要足够：不再读取全文；计算基准已齐全后用本地日期运算，不为每一步计算反复检索。

只有第一范围结果不足且另一来源有明确补充价值时，才允许一次有区别的扩展；不因一次无命中就自动搜索所有来源、联网兜底或换词循环。目标不唯一、适用学期不明或事实冲突时，优先澄清范围。显式要求跨来源比较时可在同一批次查必要来源，不强行串行兜底。

读取关闭时，不返回会话外标题、摘要或正文，也不通过缓存、预加载或角色提示注入全局知识。日期有效性、候选状态、权限及写前版本检查由本地核心负责，不为这些机械检查额外调用模型。

## 3. 检索步骤与建议初始预算

先用已有本地索引做带过滤的查询，返回排序后的少量标题、相关片段、稳定 ID、版本和来源；模型只在片段确实不足时批量请求必要详情。独立且确定需要的读取可以同批完成，避免逐条往返。无须读取每个命中的完整 Markdown；不新增向量库、embedding、云端重排或后台全量扫描来满足本轮需求。

以下为可调整的初始实施预算，不是用户已指定数值，也不是性能实测结论：

| 范围 | 建议默认上限 |
|---|---|
| 每条用户请求的本地检索工具往返 | 2 轮：首次检索，必要时补充检索或详情；同轮可批量调用 |
| 索引搜索 | 合计 2 次，覆盖所有本地来源，不为每个来源单独重置 |
| 每次搜索返回 | 最多 5 个命中，每项相关片段最多 300 个 Unicode 字符 |
| 详情读取 | 合计最多 3 个对象/片段，每项最多 1200 个 Unicode 字符 |
| 本轮检索结果进入模型的累计内容 | 最多 6000 个 Unicode 字符，并受模型剩余上下文预算限制；不是 token 数估算 |

全文长于预算时按相关段落返回，标注截断和位置，不静默截断后声称已读全文。达到预算后停止追加检索，基于已有结果说明结论与未覆盖项；若确实不能完成，提出具体缺项或分批范围，不静默扩大预算。用户明确要求全库梳理时可设计分批任务，但每批仍有限额并报告实际覆盖，不能把普通问答变成后台全库扫描。

同一用户请求中的重复查询/详情请求做去重；预算计入模型发起的检索请求及其结果，即使命中本地缓存，也不能以零 IO 为由无限继续工具往返。各轮沿用同一总账，不在失败、重试或来源切换时重置。响应等待继续复用现有总时限，不在每轮重新开始完整请求计时。

## 4. 有效结果复用与失效

优先复用当前会话已有、仍在上下文中且来源版本/适用范围未变的结果，不重新搜索；缺少的信息才补查。缓存先限定当前会话的有界短期结果，不把其他会话的读取内容自动注入新会话。

缓存键区分来源、规范化查询、筛选范围和来源版本代次；空结果也可短期复用。确认增改删、人工编辑、同步导入/冲突裁决、会话内容变化都推进相应来源代次；权限关闭清除可自动复用的外部片段，事实有效期或适用学期变化也使相关缓存失效。不得仅因“几分钟前查过”就忽略状态变化。

请求“最新状态”或执行写入时，必须检查当前版本；缓存不代替写前并发校验。去重键、目标存在性、审批及 revision/hash 一致性等必要业务校验不属于可省略的 AI 检索；它们只执行必要本地检查，不向模型额外暴露无关内容。

## 5. 定向验收与观测

实现后以确定性模型/工具模拟验证策略，再做单独授权范围内的真实模型抽样；不凭文档或模拟结果保证线上模型永不多查。记录每轮检索次数、来源、返回字符数、耗时、缓存命中/失效和停止原因，不把全文、Key 或完整个人问题写入性能日志。

必要场景：寒暄/改写/已给日期计算 0 次检索；读取关闭 0 次会话外读取；学期基准缺失只查适用全局事实；命中足够即停；同问题不重复查；无命中不全库兜底；同期事实更新/确认删除/同步导入后旧缓存不用；不明确目标先澄清；跨来源比较与大范围任务有界分批；超预算、取消、超时后不继续工具循环；节省检索不跳过写前版本和审批检查。

以这些场景的工具调用计数、结果量与时延比较改造前后，不预先承诺百分比提速或费用下降。预算只覆盖本端工具编排；若未来当前模型接口内置联网不暴露其内部检索次数，只能限制可见请求和本端总时限，不能声称能约束服务商内部每次搜索。
