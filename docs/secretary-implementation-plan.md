# 懒狗秘书改造：实施任务与验收门禁

日期：2026-10-20。状态：计划细化，尚未开始业务实现或运行新矩阵。用户已确认修改完成后执行三端合计 100 例：手机 AVD 50、平板 AVD 25、Windows 桌面 25；不是每端 100 例，也不代表授权整个项目全量测试。

## 1. 需求与完成口径

本计划落实 [AI 对话计划](ai-conversation-redesign-plan.md)、[秘书与全局知识计划](secretary-and-global-knowledge-plan.md)、[检索策略](ai-retrieval-policy.md) 及 ADR 0017/0018，不替代术语、同步和凭据约束。具体 100 例见[新功能验收矩阵](testing/secretary-100-case-plan.md)。

完成业务修改后，先通过直接受影响的局部测试，再串行执行手机 50 → 平板 25 → Windows 25。全部 100 个 ID 在同一候选代码版本上有真实执行记录后，才可报告本次矩阵结果；旧矩阵 2026-10-18 的通过记录不可复用为新功能证据。

Windows 使用本机 Flutter 桌面集成测试，不把主机尺寸模拟称为 Windows 模拟器。Android 使用实际 AVD 视口，不用主机 widget 测试冒充手机/平板执行。

## 2. 基线与前置条件

- 当前已核对的运行基线：设置快照 schema 2、会话 SQLite `user_version=1`、成果索引 SQLite v3；生产无 `AppController`。实施时冻结提交 SHA 并再次检查相关版本，目标版本按实际变更递增，不硬覆盖并行产生的迁移。
- 继续使用 `AppRuntime` 装配，UI 只依赖模块，成果写入由 `ResultLibrary` 协调。沿用 Markdown 权威、SQLite 索引/独立账本、稳定 ID、版本/hash、可恢复提交、墓碑和冲突处理。
- 不安装在真实用户目录上做故障或恢复测试；每例使用合成资料、独立 vault/数据库/非秘密配置。升级夹具来自旧 schema 的合成数据库和配置，保留现有真实目录不动。
- Flutter/Dart 沿用仓库锁定版本；复用已有双 AVD、Gradle 缓存和 Windows 工具链。启动前检查设备身份、端口和逻辑尺寸，仅回收脚本本次创建的模拟器。
- OneDrive 真实接入仍未完成。应用侧全球知识同步先复用现有 Provider 契约和受控远端验证；实际三端云盘共享的交付还依赖真实 Provider 接入，不能以受控同步通过宣称 OneDrive 已交付。

## 4. 数据与操作契约细化

### 权限和状态保存

- 三个布尔能力：读取、新增、修改与删除；新会话复制当时默认值，旧会话迁移时固定快照，临时新页在首次发送落库。修改总默认值不追改已有会话。
- 默认权限随可移植设置导入导出；会话快照随本端会话保存，不进入成果同步。端身份和 Key 规则不变。
- 关闭权限取消该请求尚未提交的相关动作，恢复重放再次检查；已提交动作记录真实结果，不能以取消为由隐藏成功写入。

### 工具边界（建议内部名称，实施时与现有契约对齐）

| 工具类别 | 最小输入 | 本地强制检查 | 返回 |
|---|---|---|---|
| 成果/事实搜索 | 查询、来源、类型/日期/学期筛选、受限条数 | 读取权限、明确范围、预算、候选/过期/冲突排除、查询参数绑定 | 少量相关片段、ID、版本、来源、截断标记 |
| 已知成果详情 | 稳定 ID、所需字段/片段 | 读取权限、ID/可读状态、字符预算；不接任意磁盘路径 | 必要字段与版本，缺失/失效原因 |
| 其他会话搜索/片段 | 查询或会话/消息 ID、片段范围 | 读取权限、文字范围、预算；不提供 AI 会话改删工具 | 消息片段与可跳转来源 |
| 新增/修改/删除普通成果 | 类型/字段；修改删除带目标和预期版本 | 相应写权限、schema、日期/归属/目标、CAS、动作键；原/新对象均检查全局用途 | committed/rejected/failed、对象 ID/新版本、真实理由及撤销入口 |
| 提议全局知识变更 | 操作、目标/预期版本、拟写内容、适用范围/依据 | 相应权限、候选内容/版本、去重；不提供模型确认工具 | pending 的候选 ID，明确尚未生效 |

实现应扩展现有模块而非堆到单个控制器；模型不接收任意 SQL、文件路径或“跳过审批”字段。业务上必须存在的内部版本/审批/去重校验不受“少检索”优化删除。

### 全局事实、审批与撤销

- 全局事实复用 `knowledge`，建议显式用途字段加事实标识/值、适用范围、有效期和确认版本信息；具体字段名及 Markdown schema 在 S0/S3 冻结，未知旧字段仍往返保留。不要通过普通标签或标题推断审批等级。
- 候选状态：pending → approved/rejected/stale；approved 后提交还须检查权限与目标版本。提交成功才标 applied，失败保留可见原因；恢复时不得重复提交或自动把 stale 变 approved。
- 确认绑定候选 ID、载荷摘要及目标 revision/hash，编辑候选后重展示。原对象或新对象为全局范围时都执行审批，禁止先取消用途标识再直接改删。
- 撤销账本保存前像、提交后版本、动作状态和到期时间，独立于会话外键级联；建议统一 10 分钟窗口，S2 固化实现值并测试虚拟时间，禁止靠长时间 sleep 验证。普通成果手工撤销直接执行，全局知识撤销/恢复须确认其实际变更。
- 成果导入、确认变更、删除和冲突裁决更新检索代次；同步只传已确认 canonical 版本与墓碑。批准一次的同版本在其他端接收不重复审批，冲突依旧人工裁决。

## 5. 具体界面行为

手机顶部保持历史菜单/标题/权限/新对话；权限面板只有三组开关并显示当前会话状态。空态显示“懒狗秘书”的简洁欢迎内容；底部输入区包含文本、附件、语音、思考、联网及发送/停止。朗读放回复操作区。

从应用导航进入 AI 页新建临时页；从抽屉继续会话不创建新会话。弹出键盘、权限面板、系统文件/图片选择、旋转/宽度变化只重建视图，不重置当前内容。失去页面后仍在执行的生成须有明确停止/状态规则，不能因隐藏页面而偷偷追加多轮检索。

宽屏会话列表与正文分栏；“待处理”和“全局知识库管理”有独立入口，侧栏专用于会话。来源点击打开相应成果/消息；审批卡在对话和待处理页同步状态；撤销失败说明版本变化/到期原因。

### 环境与证据

- 手机 AVD：沿用已存在手机 profile，真实逻辑宽度 <600；平板 AVD：宽度 ≥600，实际 profile 和分辨率写入 manifest。不凭 AVD 名称猜设备尺寸。
- Windows：真实桌面 renderer，1440×900 逻辑视口为默认，矩阵中的宽窄/缩放场景显式覆盖。浅深色、字体 1.0/1.15/1.3 和键盘场景分配到指定例，不重复乘成另一套数量。
- 先确认端口 5560/5562 可用及 AVD 对应身份，串行启动；启动 helper 使用隐藏窗口。麦克风/朗读探针不能沿用禁音参数后声称测过真实声音；相应探针单独配置并记录。
- 模型使用确定性 SSE/工具脚本；同步用可控 Provider 和多个隔离 vault，日期用固定测试时钟，语音/文件端口仅在对应合同场景中注入。UI 操作和最终存储断言仍经过生产模块与真实设备。
- 持久化、迁移、重启、审批/撤销恢复等场景必须用真实临时文件和 SQLite，不能仅 dispose/recreate 内存状态就声称验证进程恢复。Flutter 重启模拟与真实 OS 强停/重启探针分别记录。
- 真实模型抽取质量、真实云盘/OAuth、真实识别与扬声器出声不在模拟端口证据中；可用性探针和真实联调另记，不混写为 100 例已覆盖。必要产品能力未实现时，不能因为替身测试通过标注功能完成。

### 日志、重跑与完成判定

最终报告写入 `test-results/secretary-100-final/<run-id>/`，包含 `manifest.json`（SHA/脏状态、工具版本、设备、能力/注入模式、测试时钟）、每例 JSON/Markdown、每端日志、失败截图/状态摘要、检索计数/字符量与耗时及汇总。临时数据放 `tests/agent-temp/secretary-100/<run-id>/`；可在设备私有临时目录运行，但对应种子/索引清单归档到任务路径。不要把 Key、真实用户正文或完整数据库转储混入公开报告。

100 例每个 ID 只计一次，失败重试不增加分母；记录通过、失败、未执行、阻塞，不把 skip 算通过。只有 50/25/25 均执行且全部通过，才写“本次三端矩阵 100/100”；否则写实际计数和未完成范围。

修复后仅重跑受影响例及直接依赖验证，记录代码差异和影响映射；未受影响且环境相同的通过结果可复用。最终汇总必须能把每个 ID 的有效证据关联到最终候选版本；无法证明旧结果不受变更影响时才重跑对应范围，不因准备提交重复执行全矩阵。

完成 S12 后更新 README/RM 与测试报告，记录实际检查与未覆盖项；功能任务按原子提交规则提交并检查工作区干净。不自动发布、推送或改写旧版本发布结果。
