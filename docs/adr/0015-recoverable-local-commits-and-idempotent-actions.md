# 本地持久化使用可恢复提交与幂等动作

成果文件替换、SQLite 索引更新和捕获/自动记录审计是不同的持久化动作。所有成果写入由成果库协调：使用唯一操作 ID、唯一暂存文件、旧版本恢复副本、预期 revision/hash 和持久化提交日志；只有校验通过后才更新索引并清理恢复材料。启动时按已登记阶段恢复，不凭猜测覆盖文件。

捕获和模型工具调用使用稳定动作键及分阶段账本。完整模型响应先持久化，恢复可继续尚未完成的本地写入；应用重启后未完成的网络请求标记为中断，必须由用户手动重试。相同动作重复执行复用原成果 ID。

索引库、会话库与非秘密设置分别版本化。迁移在业务写入启动前备份数据库一致性快照和配置；涉及多个库的升级使用单一迁移清单，任一迁移失败则恢复整组备份。Markdown 可重建派生成果索引，但不能重建捕获原文、会话、图片、动作审计或迁移状态。密钥继续留在系统安全存储，不导出或写入普通备份。

代价是需要维护提交日志、备份和恢复测试；收益是进程中断、索引落后和重放不再造成静默丢失或重复成果。
