# 专用秘书采用可恢复任务、应用内完全权限和写入前查重

2026-11-03 用户确认的目标；2026-11-04 进入实施与验收，2026-11-08 实现提交为 `111f996` 并进入 v1.3.0 Android 手机预发布。秘书在现有 Flutter 本地核心中采用持久化任务和真实工具回执，支持多步执行、写后检查、分批继续和中断恢复；模型权限由本地执行点校验。完全权限作为会话可选预设，允许软件内任意表及内容、字段和全局知识直接增改删；标准模式保留结构和全局知识逐项确认，既有会话和升级默认不扩大授权。

> 2026-11-08：累计 2 小时/240 次请求预算、追加额度和“无法判定的查重冲突暂停”由 [ADR 0025](0025-unbounded-flutter-agent-harness.md) 取代。完全权限下无法证明同一对象时新建独立条目并标记待核对；其余权限与恢复规则继续有效。

完全权限允许删除三个初始默认表，因此把它们改为仅首次初始化创建的预置收纳表，收纳目标独立映射，删除后不会因重启重建。没有收纳目标的输入留在本端捕获账本待归表。此目标取代 ADR 0020/0021 的默认表永久保护，以及 ADR 0018 的“所有模式均逐项确认”规则；ADR 0017 的会话授权原则继续有效。标准模式的结构审批继续有效，完全权限的直接执行不增加相同权限的逐次审批。

所有正式自动录入经过统一查重接收：同操作幂等，同一业务内容复用，有兼容补充自动整合到原条目，只有无法解决的身份/事实冲突才询问。相同标题不等于同一事件，不同发生日期和周期保持独立。检索、分页和读回检查返回实际覆盖，提交在本端写锁内复核查重结论和对象版本；操作意图、前像及回执支持恢复，未定状态暂停而非盲目重放。该保证只覆盖本端受管写入，不宣称已经实现跨设备去重。

选择这些规则是为解决工具后无法核对和多入口重复信息；代价是维护授权来源、可恢复操作账本、收纳映射和语义查重。完全权限不是操作系统或凭据权限，不包含修改自身授权。历史设计中的两小时/240 次请求额度已由 ADR 0025 取消；当前实施细节与验收矩阵见[专用设计](../secretary-agent-design.md)，参考事实见[研究记录](../research/04-dsh-agent-permissions-and-runtime.md)。本 ADR 接受产品与架构目标，不表示运行代码已具备这些能力。
