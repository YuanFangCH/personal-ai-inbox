# 采用模块化本地核心与兼容迁移

本地核心不再由一个应用控制器承载全部状态和用例。端配置、成果库、捕获、会话、同步各自形成深模块：对外提供小 interface 和不可变快照，内部隐藏 Markdown、SQLite、模型流、附件、冲突和重试细节。组合根只负责装配与生命周期，不承载业务命令。

成果写入只允许经过成果库模块。捕获和自动记录都不能绕过它直接修改 Markdown 或 SQLite，确保一个成果一个文件、稳定 `id`、`revision`、墓碑和索引可重建等不变量只有一个 owner。对话、捕获和同步可以共享策略模块，但不能重新形成新的 god object。

迁移期保留现有应用控制器作为兼容 facade，让 UI 和既有测试逐步切换，避免双状态并行。facade 只能委托模块，不能重新复制实现；所有调用方迁移后删除 facade。模块依赖方向固定为 `ui -> modules -> domain -> adapters`，UI 不得直接依赖数据存储、SQLite、Markdown 或厂商客户端。

只在存在生产 adapter 和测试 adapter 的依赖上设置端口，例如同步通道、模型端点、端配置存储和平台捕获入口；纯规则和单一实现不增加额外 interface。通用事件总线、service locator 和以文件行数为目标的机械拆分不采用。

代价是装配代码增多、模块间需要显式传递快照和命令，迁移期间会短暂保留兼容 facade；收益是修改同步、模型、捕获或成果存储时能够把变更、测试和故障定位收口到对应模块。
