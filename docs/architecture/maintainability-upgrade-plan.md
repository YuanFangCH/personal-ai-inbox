## 目标、范围与验收

关闭架构审查 F1–F12，并在每阶段完成后以一个原子提交交付。保留 Android、Windows 用户成果、会话、图片、端标识和凭据；使用合成数据和临时目录验证。Markdown 继续作为成果权威副本。Web 保持预览用途，其会话和图片的内存存储不列入正式耐久性承诺。

本轮不实现 OneDrive、百度网盘、通知、后台调度、正式签名或自动发布。现有演练 Provider 用于验证同步算法。应用崩溃与可注入 I/O 故障属于验收范围；未执行断电专项测试前不承诺断电耐久性。

安全和协议不变量固定：自动记录只新增、置信度不低于 0.85、10 分钟撤销、用户关闭图片出网后任何路径均不发送图片、OneDrive 冲突按远端版本裁决、成果采用既定 +08:00 语义和墓碑协议。未知模型默认只支持文本。应用重启后不自动重发未完成模型请求；完整响应已经持久化的本地动作可以恢复。

最终门槛：格式检查与 `flutter analyze` 无问题；原有测试全部通过；正式回归覆盖本次修复；Windows/Android/Web release 构建通过，原生与 AVD 验收按实际执行记录。未验证能力继续标记未验收。

## 阶段与行动

每阶段先运行针对性测试，收敛后运行完整主机测试；更新交接记录并通过正常 Git hooks 提交。失败时留在当前阶段。

2. 统一方案与协议中的成果字段名、索引/账本恢复范围、模型凭据存储说明、知识搜索语义和“不实现向量索引/静态站”的范围。
3. 新增 ADR 0015（可恢复本地提交及动作幂等）与 ADR 0016（数据库/设置迁移与同步裁决）；更新 ADR 索引与同步协议。
4. 修复已有 Dart info lint；将 CI、Release、PowerShell 验证脚本固定到 Flutter 3.47.6 / Dart 3.13.5，不升级依赖。
5. 执行格式、分析、完整测试和 `git diff --check`。

阶段门槛：294 项现有测试全通过、分析零问题。提交：`chore(architecture): 固定整改基线与恢复契约`。

### B. 模型请求与自动记录

1. 新增纯请求策略，把设置快照、会话历史转换为能力校验后的请求消息；策略不读存储、不发网络。
2. 图片开关在 HTTP 请求构造前执行，覆盖历史消息、系统分享、相册/拍照和重试。关闭时保留本地附件；含文字图片消息只发送文字，纯图片消息留本地并提示。
3. 能力声明分别控制图片、工具、JSON 输出。未知模型只允许文本；无工具能力时文字聊天可用但不调用自动记录。
4. 流契约区分增量、完成、取消、中断、超时和协议错误。`[DONE]` 或有效 `stop/tool_calls` 为正常完成；截断、过滤、解析错误或无完成信号 EOF 都不执行工具，完成后忽略数据。
5. 加入响应头 45 秒、流空闲 60 秒、总时限 300 秒。有效范围依次为 5–120 秒、10–180 秒、30–600 秒，总时限不得小于另两项；SSE 心跳重置空闲计时，所有 HTTP 读取受期限约束，取消释放网络资源。
6. 工具调用要求正确字段、准确类型、无未知字段；置信度须为有限 `[0,1]` 数字，日期提供时必须有效，结束不得早于开始。非法结构不产生副作用；低置信、敏感、日期歧义、过去日期和重复规则进入待整理。
7. 同一会话串行写入消息；完成保存等待增量写入；取消等待旧请求结束。无论保存结果如何都释放运行状态。重试保留原用户消息和附件，建立独立生成尝试。
8. 将临时探针替换为正式单元/模块测试，覆盖图片开关、正常/异常终态、延迟与取消、严格校验、能力降级和重试保留。

阶段门槛：不完整响应或无效候选不创建成果；图片关闭时所有请求均不含图片字节。提交：`fix(model): 执行图片策略并严格校验自动记录`。

### C. 可靠写入、迁移与恢复

1. 在 Markdown 同目录使用唯一提交 ID、唯一临时文件、旧版本恢复副本和 `.json` 提交日志，记录成果 ID、旧/新路径、旧/新 hash、预期 revision 和提交阶段。恢复目录不属同步白名单。
2. 同一成果串行写入。提交前校验实际文件 hash 与 revision；版本过期返回冲突，不覆盖编辑。类型变更先写入并索引新路径，再删除旧路径。
3. 写入次序固定为：暂存新内容并校验 → 持久化恢复副本 → 持久化提交意图 → 替换成果文件 → 校验目标 hash → 更新索引 → 标记完成 → 清理恢复材料。失败返回明确阶段。
4. 启动扫描提交日志：目标等于新 hash 时补索引；目标未提交而完整暂存可恢复时完成原操作；新内容不完整时恢复旧副本；信息不足时保留所有副本、进入只读错误状态并报告，不猜测选择。
5. 为索引库和会话库建立独立 SQLite `user_version` migrations。当前数据库按 0 版处理，不改变既有业务列语义。幂等账本不得随成果索引重建而清空。
6. 执行迁移前，在应用业务尚未启动时创建索引库、会话库和非秘密配置的校验备份；现存 Key 保留在系统安全存储，备份不包含 Key 值。快照失败就不开始迁移。
7. 用迁移清单协调两库升级；全部迁移及结构校验完成后一次开放写入。中途失败或重启发现未完成清单时恢复整组备份，再进入维护错误状态；降级通过备份恢复。
8. 建立持久动作表：捕获键为捕获 ID，模型工具键为助手生成 ID + 工具序号；记录目标成果 ID、内容 hash、来源、阶段与最终结果。`prepared → resultCommitted → completed` 可重复执行。
9. 完整模型响应及工具参数先落会话库并标记请求完成，再登记及应用本地动作。恢复时补做完整响应的本地动作；未完成模型请求标记 interrupted，要求用户手动重试。
10. 捕获 `processing` 恢复成保留原文的待整理项。重复确认、回调、恢复通过原动作 ID 幂等执行。
11. 重建成果索引返回成功/失败总数和按路径诊断；坏文件原样保留；重复成果 ID 不覆盖。成果文件未知字段往返保留、缺少 schema 版本视旧格式、较新未知 schema 只读拒绝写入。
12. 使用临时真实文件与 SQLite 注入暂存、恢复副本、提交日志、替换、索引、动作审计阶段故障；重复恢复后成果数量不增加。测试不读取生产 vault 或 Key。

阶段门槛：中断后可恢复旧内容或已登记新内容；无静默丢失、重复成果或半迁移。提交：`fix(storage): 增加可恢复写入迁移与动作幂等`。

### D. 同步、裁决与成果快照

1. Provider 条件写入明确区分“对象必须不存在”与“匹配 eTag 更新”；条件失败和非法对象有稳定错误类型。
2. 下载校验远端元数据 ID、frontmatter ID、类型目录、稳定文件名、canonical 状态及重新计算的内容 hash；拒绝路径越界和身份错配。
3. 每轮读取 Markdown 当前 hash，不盲信旧 SQLite 值；接收远端前重新读取本地版本，防止并发覆盖。相同内容建立基线。
4. 冲突记录含成果 ID、远端 hash/eTag 和副本路径；同一远端版本只创建一次，重复轮次不再提升 revision。
5. “保留本地”裁决保存本地 hash 与所见远端版本，用该 eTag 条件上传；成功后才更新同步基线。“使用远端”通过成果库导入原始内容并保存对应基线。
6. 裁决后远端再次变化时重新冲突；条件失败每对象每轮最多重判两次，之后保留待处理；不静默覆盖。
7. 墓碑与普通成果都走同一校验/导入路径，不让草稿进入演练同步。
8. 所有下载与裁决通过成果库写入、更新快照，再通知 UI；失败只更新失败状态。同步不直接碰 raw store。
9. 回归覆盖身份/hash 错配、首轮同内容、两种裁决、重复冲突、新并发变更、墓碑、单项失败及单索引恢复。

阶段门槛：裁决后下一轮收敛，新的并发变化仍保留，UI 快照与磁盘一致。已通过 Flutter 3.47.6 / Dart 3.13.5 格式检查（143 文件零变化）、静态分析（0 问题）、完整主机测试（332/332）和同步/裁决/SQLite migration 定向测试。未执行 release、原生/AVD、真实云盘与断电专项验收。提交：`fix(sync): 校验远端身份并使冲突裁决收敛`。

### F. 设置与最终验收

1. 把普通设置迁移成有版本的完整快照；保留现存端 ID、模型配置和图片开关；非法历史值留存并提示，不静默放宽安全策略。
2. 能力覆盖顺序：显式用户覆盖优先于内置模型声明；未知模型仅文本。能力测试失败不反向修改配置。
3. URL 为无用户信息/query/fragment 的 API 根 URL；允许 HTTPS 和 loopback HTTP。连接路径只在 adapter 追加 `/chat/completions`。
4. 高级设置采用以下范围：响应头 5–120 秒默认 45；空闲 10–180 秒默认 60；总时限 30–600 秒默认 300 且不小于前两者；上下文 2–20 条默认 20；含图消息 0–4 默认 4；图片 0–8 张默认 8。只有收到持久化配置快照后 UI 才刷新。
5. Key 用安全存储暂存槽更新：新槽写入成功后切换普通设置指针；切换失败保留旧槽。日志、配置导出与备份清单不含 Key；导入导出只含可迁移非秘密偏好，恢复默认不改端 ID/Key。
6. 连接测试为用户主动动作，发送固定文本、不带历史或图片；返回诊断但不自动开放模型能力。
7. 完成 Android/Windows/Web release、Windows smoke、Android AVD smoke 和现有设备矩阵；真实云盘/通知/密钥网络实测仍列未验收。
8. 对照 F1–F12 逐条记录证据、剩余限制、版本升级/恢复说明及 Web 预览提示。

阶段门槛：静态分析与全部测试通过；发布构建及已执行的平台冒烟通过。提交：`feat(settings): 增加高级配置并完成架构整改验收`。

## 模块接口与恢复语义

| 模块 | 对调用方承诺 |
|---|---|
| ResultLibrary | 幂等创建、期望版本保存、受验证导入/裁决、按 ID 查询和分页、列举重建诊断 |
| ModelPort | 分类、可取消流、明确终态、连接测试；自身不持久化或执行工具 |
| SyncProvider | 条件写入/读取对象与稳定错误；不决定业务冲突 |
| ActionLedger | 稳定 idempotency key、目标 ID 复用、阶段更新和未完成操作查询 |
| DevicePreferences | 版本化快照、校验写入、能力设置、非秘密导入导出 |
| AppRuntime | 装配、迁移/恢复门控、异步关闭；不持有业务命令 |

SQLite 账本迁移与索引分开。仅成果索引、反向关系、派生搜索字段可从 Markdown 重建；捕获原文、会话、图片引用、工具审计、迁移记录和动作账本须由对应本地数据库/备份保留。数据库一致性备份使用 SQLite 快照能力；应用运行期间不得复制活跃 WAL 数据库主文件当作完整备份。

## 验收与提交门禁

- 阶段 A–E 每阶段运行格式、静态分析、定向回归及收敛后的完整主机测试。2026-10-13 用户明确要求阶段 F 只跑受影响的分级/定向测试，完整套件留到发布时再运行；不得因阶段记录而重跑全量。
- 存储恢复使用临时目录和真实文件 adapter；网络故障使用 MockClient；绝不向测试写入真实 Key、vault 或附件。
- 测试覆盖审查 F1–F12、迁移、配置保存回滚、schema 兼容、同步冲突收敛和资源释放。
- 完成后构建 Web/Windows/Android，运行 Windows integration 与 Android AVD smoke/UI 矩阵。未运行项在交接中标出。
- 阶段失败则留在当前阶段，保留诊断材料但不提交失败测试/半迁移。
- 每阶段更新 `RM_HANDOFF.md` 的状态、进度、验证、风险、下一步和顶部变更记录；全文件暂存，通过 `git diff --cached --check` 与常规 hooks 后用指定 Conventional Commit。提交后 `git status --short` 必须为空。
