# 升级与恢复说明

## 数据边界

- 成果的权威副本是 `vault/<类型目录>/<id>.md`。SQLite `index.sqlite3` 的成果、关系和查询行是派生索引；索引删除后可以扫描 Markdown 重建。
- `conversations.sqlite3` 保存会话、消息、附件引用、生成记录和自动记录审计；这些数据不能从成果 Markdown 重建。捕获原文和幂等动作也由索引库独立表保存。
- 图片附件、会话和动作账本不属于成果同步白名单。Windows/Android 使用本地持久化 adapter；Web 的会话、图片和索引仅为内存预览 adapter。

## 应用升级

启动时应用先取得 `.migration-startup.lock`，检查索引库和会话库 `user_version`。当前索引库版本为 3，会话库版本为 1。发现较旧版本时，应用在打开业务工作区前使用 SQLite `VACUUM INTO` 建立数据库一致性快照，并备份非秘密设置快照；Key 值继续留在平台安全存储。

迁移期间写入 `.migration-state.json`。两库完成迁移和版本校验后才释放启动锁。若重启发现迁移仍处于 pending，应用会验证备份清单并自动恢复两库与非秘密设置，然后重新启动迁移。更高版本数据库或损坏的迁移清单会停止启动并保留备份材料，避免以旧代码覆盖新数据。

旧偏好键在首次加载时迁移到版本化设置快照（当前配置 schema 为 2）。旧端 ID、模型地址/名称、主题和图片开关会保留；旧 API Key 由旧安全存储键读取，直到用户更换密钥时才轮换到新槽。Key 更新先写安全存储暂存槽，再以单次快照写入切换槽 ID；快照写入失败时清理暂存槽并继续使用旧配置。无效设置值保留在快照中，设置页提示修正，模型请求不会使用无效配置。

## 成果文件恢复

每次成果写入在 `vault/.local-transactions/` 生成唯一暂存文件、旧版本副本和提交日志。启动恢复依据日志中的成果 ID、路径、revision 与 hash 选择：完成已登记的新文件、补齐索引、恢复旧副本，或在无法判定时停止并保留所有材料。新的成功提交后会清理临时材料。

设置页的“从 Markdown 重建索引”会扫描成果文件、只更新变化的索引行，并显示坏文件路径。未知 frontmatter 字段会随成果编辑保留；缺少 `schema_version` 按版本 1 读取；较新未知格式版本或重复成果 ID 不会被选作可写索引条目。SQLite 索引库当前 schema 为 3，会话库为 1；索引新增规范化搜索字段后仍以 Markdown 文件为权威。

应用关闭时先停止模型生成、等待消息队列和成果/配置写入排空，再关闭 SQLite 与会话存储。未完成的网络模型请求启动后标记为 interrupted，用户必须手动重试；已持久化完整响应的本地动作可以幂等恢复。

## 验收边界

已用合成旧数据库、临时文件、注入写入错误和进程恢复测试验证上述路径。没有升级真实用户 vault，也没有做物理断电专项测试；因此当前证据不承诺任意硬件断电时的耐久性。云盘同步仍为内存演练通道，不能作为备份或恢复来源。
