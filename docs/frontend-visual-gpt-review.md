# 前端改版辅助评审与主方案收敛

日期：2026-10-25。状态：三轮网页讨论已完成，Codex 已筛选并合并设计建议；仍处于规划阶段，未开始 Flutter 实施。

## 协作方式与材料

用户要求使用侧边网页版 ChatGPT 的“聊天”模式讨论，并进一步明确“把他当成一个辅助你完善计划的子 agent，以你为主”。Codex 负责事实核对、质疑与取舍；网页回复是候选意见，不是用户授权或独立验证。

网页初始状态已确认聊天选中、工作未选中。发送的是项目用途、三端形态、现有功能、业务边界、六张参考图的布局描述和当前改版草案，未发送密钥、用户成果、私人会话/头像或原始截图。网页评审者没有访问仓库、原图、运行中的应用或真实账本；涉及尺寸和行为的意见均是设计推演。

主方案见[前端视觉与动效改版方案](frontend-visual-redesign-plan.md)。本记录保存讨论结论而非逐字抄录回复；网页版对话留在用户的当前聊天中，不将私人会话链接写进公开仓库。

## 三轮讨论

| 轮次 | Codex 提问/反查 | 网页反馈与处理 |
|---|---|---|
| 第一轮：整体设计评审 | 介绍项目和约束，询问换皮风险、手机底栏、桌面侧栏、首页与成果操作 | 建议区分内容密度、AI 页隐藏底栏、历史独立滚动、回执与审批独立；提出权限移位和动态条数等建议，Codex 未直接接受 |
| 第二轮：约束与状态细化 | 明确顶部权限不可移动，拒绝复杂动态条数算法；追问输入区状态、低高度导航、真实动作账本与动效优先级 | 接受两项纠正，细化互斥输入层、真实状态与固定预览上限；其生成返回和侧栏细节仍有问题，Codex 再次反查 |
| 第三轮：主方案回传 | 根据源码纠正取消生成与候选状态，给出紧凑核心导航/更多方案，要求只反查明显漏洞 | 提醒未发送内容、迟到回调、极低窗口可达性及状态映射；未提出需推翻的设计问题。Codex 将必要项纳入局部验收，未将评审结论当作已测试事实 |

## 主要取舍

| 主题 | Codex 最终整合到草案的建议 | 未采纳或限制 |
|---|---|---|
| 全站统一 | AI 阅读宽松、首页适中、日历/列表紧凑、编辑/审批有结构，共享基础视觉规则 | 不让所有页面都套大圆角卡片或聊天页式留白 |
| 手机底栏与返回 | AI 页始终隐藏主底栏；顶部保留菜单/标题/权限/新对话；抽屉首项“返回首页”，系统返回先关临时层再离开 | 不移动用户明确指定的顶部权限，不再在窄顶栏塞第五个元素；原预览底栏未同步 |
| 会话与生成 | 选图/键盘/权限/抽屉不重置会话、不清内容；真正离开继续原有取消生成行为，已提交成果不回滚 | 不采纳“返回后默认后台继续生成”；不新增跨会话草稿库，也不承诺退出/新对话自动保存未发送素材 |
| 桌面侧栏 | 核心首页/日历/事项/知识 2×2 紧凑区，底部更多含全局知识/待处理/设置/同步，历史独立滚动；极低高度折叠历史且入口可达 | 不列八个纵向常驻入口挤没历史，不压小点击热区，不新增命令面板 |
| 首页 | 原三块、原排序，手机上限 3/4/3、宽屏 4/6/4；整页滚动与完整列表入口；以标题/留白/细线组织 | 不做按屏高/重要性动态算条数；不要求首屏见到全部板块，不重新引入统计 |
| 普通成果 | 回执显示动作/对象/真实状态/撤销；网络失败与提交状态分开，未核实时不盲目重写 | 不从模型文本推断成功，不把停止生成当作撤销，不在 UI 重建幂等或事务逻辑 |
| 全局知识 | `pending/approved/applied/rejected/stale/failed` 全部有对应展示；确认绑定所见 digest | 不把“确认待提交”当作“已完成”，不自动批准变化后的版本，不新增通用 diff 引擎 |
| 动效 | 抽屉/托盘/输入位置/真实状态优先，勾选/切页/新消息一次性入场随后 | 不做逐 token、历史重播、首页首屏逐行飞入或视差 |

## 源码核对与未解决事项

- `app/lib/ui/pages/conversation/page_actions.dart` 的 `_disposeConversationPage` 在离开时调用 `cancelGeneration`；新对话会清理当前临时输入。保留该生命周期边界，不因参考界面或网页建议改成后台任务/草稿持久化。
- 同一文件当前 `_send` 在等待发送完成前清理输入与素材。因此“本地提交失败应保留/可恢复本轮内容”是后续 D2 需核对的呈现/本轮暂存要求，不能宣称当前已保证，也不能与模型失败后已有用户消息的重试混淆。
- `app/lib/core/models.dart` 的账本含 `prepared/applied/undoing/undone/expired/failed`，候选含 `pending/approved/applied/rejected/stale/failed`。`app/lib/core/chat_models.dart` 的聊天动作回执状态较少，不能假设它已经完整映射账本。
- `ResultLibrary.reversibleActionForKey` 已存在，但 UI 接线、动作键对应和撤销入口仍需在 D2 定向核对；本轮不证明所有账本状态已可直接从聊天组件取到，不借视觉任务静默扩展核心接口或修复未评估的业务逻辑。
- 对“新对话/离开/切换历史遇到未发送素材时提示放弃”的建议暂列 D0 可选交互，未纳入默认增加弹窗；当前必须避免改版引入额外清空，不承诺沿用旧行为就等同已解决所有草稿丢失风险。
- 后续局部验收补充：辅助层返回不取消请求、真正离开停止且迟到回调不污染新会话；本地发送失败与网络生成失败分别验证；极低窗口的首页/更多/历史均可达；确认待提交/提交失败/过期/版本变化不被错误显示为成功。
